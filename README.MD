# Лабораторная 3: Создание веб-сервиса для бэкенда системы

## Цель работы
- Создание веб-сервиса в бэкенде для использования в SPA.
- Реализация полной бизнес-логики приложения (кроме авторизации).
- Подключение к БД и тестирование через Insomnia/Postman.

## Описание задания
1. Разработать RESTful веб-сервис со следующими требованиями:
   - Методы и URL должны соответствовать принципам REST.
   - Все адреса методов начинаются с `/api`.
   - Взаимодействие с БД через ORM.
   - Записи в статусе "удален" не передаются на клиент.
   - Изображения услуг хранятся в MinIO.

2. Реализовать управление статусами заявок:
   - Создатель: удаляет и формирует черновик заявки.
   - Модератор: отклоняет и завершает сформированную заявку.
   - Пользователь-создатель фиксирован через функцию-singleton.
   - Системные поля (id, статусы, создатель, модератор, даты) вычисляются на бэкенде.

3. Реализовать 21 метод API:

   **Домен услуги (7 методов):**
   - GET список с фильтрацией.
   - GET одна запись.
   - POST добавление (без изображения).
   - PUT изменение.
   - DELETE удаление (включая удаление изображения).
   - POST добавление в заявку-черновик.
   - POST добавление изображения по id услуги (замена старого).

   **Домен заявки (7 методов):**
   - GET иконки корзины (id заявки-черновика и количество услуг).
   - GET список с фильтрацией по дате формирования и статусу.
   - GET одна запись (поля заявки + список услуг с картинками).
   - PUT изменение полей заявки по теме.
   - PUT сформировать создателем (проверка обязательных полей).
   - PUT завершить/отклонить модератором (с расчетом доп. полей).
   - DELETE удаление.

   **Домен м-м (2 метода):**
   - DELETE удаление из заявки (без PK м-м).
   - PUT изменение количества/порядка/значения в м-м (без PK м-м).

   **Домен пользователь (5 методов):**
   - POST регистрация.
   - GET полей пользователя после аутентификации.
   - PUT пользователя (личный кабинет).
   - POST аутентификация.
   - POST деавторизация.

## Порядок показа
1. Продемонстрировать коллекцию из 21 запроса в Insomnia/Postman.
2. Выполнить последовательность операций:
   - GET список заявок (фильтрация по дате формирования и статусу).
   - GET иконки корзины.
   - DELETE введенной заявки (если есть).
   - GET список услуг (с фильтром).
   - POST добавление новой услуги.
   - POST добавление картинки к услуге.
   - POST добавление услуги в заявку.
   - POST добавление другой услуги в заявку.
   - GET иконки корзины.
   - GET заявки (из 2 услуг).
   - PUT изменение поля м-м.
   - PUT изменение заявки.
   - PUT завершить введенную заявку (показать ошибку).
   - PUT сформировать заявку.
   - PUT завершить сформированную заявку (вычисление стоимости/доставки).
   - POST регистрация нового пользователя.
3. Показать измененные данные через SELECT в БД.
4. Объяснить модели и сериализаторы.
5. Представить диаграмму классов с детализацией бэкенда:
   - Домены методов по URL с интерфейсами.
   - Перечислить все методы, модели, таблицы БД.
   - Связи у моделей по коду (3 варианта).

## Контрольные вопросы
- Веб-сервис, REST, RPC.
- Заголовки и методы HTTP.
- Версии HTTP, HTTPS.
- Модель OSI ISO.

## Технические требования
- Фильтрация списка услуг и заявок на бэкенде.
- Название изображений генерируется на латинице.
- MinIO используется только для добавления и удаления изображений.
- POST заявки не делать (заявка создается пустой автоматически).
- Вычисляемые поля: стоимость заказа, дата доставки, расчеты в м-м.
