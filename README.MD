# Лабораторная 8: Межсервисное взаимодействие, асинхронность, внедрение Real-time web

**Цель работы:** Реализация межсервисного взаимодействия между основным сервисом на Go и вспомогательным сервисом на Django, освоение принципов асинхронной обработки данных и внедрение элементов Real-time web для мониторинга статусов заявок.

**Задание:**
1.  **Разделение логики**: Вынос расчетной логики или процесса завершения заявки из основного Go-сервиса в отдельный микросервис.
2.  **Второй сервис (Django)**: Разработка вспомогательного асинхронного сервиса на Python/Django.
    *   Реализация HTTP-метода для выполнения отложенного действия (вычисление, моделирование или расчет оплаты).
    *   Имитация длительной обработки: искусственная задержка исполнения **5-10 секунд**.
    *   Результат: вычисление значения по формуле и обновление специфичного поля предметной области в заявке.
3.  **Модерация**: Реализация бизнес-логики одобрения заявок модератором в основном сервисе.
4.  **Документация**: Обновление диаграмм последовательности и развертывания с учетом взаимодействия Go и Django.

**Порядок показа:**
1.  **Проверка исходного состояния**: Вызов через **Insomnia** метода `GET` основного сервиса (Go) для получения списка заявок. Демонстрация того, что расчетное поле в новой заявке пустое.
2.  **Инициация расчета**: Вызов HTTP-метода асинхронного сервиса (Django) через Insomnia или с помощью кнопки в React-интерфейсе.
3.  **Демонстрация задержки**: Повторные вызовы `GET` списка заявок в Insomnia, пока не пройдет 5-10 секунд, после чего в поле результата должны появиться данные от Django-сервиса.
4.  **Корректировка**: Вызов метода основного сервиса (Go) с использованием специального ключа для изменения/перезаписи полученного результата.
5.  **Отчетность 2025**: Демонстрация скриншотов всех изменений в **РПЗ по 2025 году**, скриншотов успешного прохождения **TestVKR** и фиксация итогового объема файла РПЗ.

**Диаграммы:**
*   **Диаграмма состояний (State Machine)**: Жизненный цикл заявки (Создана -> Передана в Django -> Обработана -> Одобрена модератором).
*   **Диаграмма прецедентов**: Описание функциональных возможностей интерфейса на **React**.
*   **Диаграммы последовательности и развертывания**: Схема взаимодействия сервисов (Go как API-gateway/Backend и Django как расчетный модуль).

**Контрольные вопросы:**
*   **gRPC**: Механизмы работы, протокол Protocol Buffers, сравнение эффективности с REST в связке Go/Python.
*   **Асинхронность**: Реализация неблокирующих вызовов и обработка фоновых задач.
*   **Веб-сервис**: Архитектурные стили, стандарты взаимодействия и интеграция разнородных систем.

---

### Технические примечания:
*   **Main Service**: Go (обработка основных запросов, связь с БД, React-фронтендом).
*   **Async Service**: Django (расчеты по формулам, `time.sleep` для имитации нагрузки).
*   **Логика данных**: При создании заявки через Go-сервис расчетное поле остается `null`. После обращения к Django-сервису, поле заполняется результатом вычислений.
