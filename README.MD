# Лабораторная 4: Завершение бэкенда для SPA

**Цель работы:** Реализация полноценной системы аутентификации и авторизации в веб-сервисе на Go, интеграция Redis для хранения сессий, настройка прав доступа (Permissions) и документирование API с помощью Swagger. Подготовка расчетной части пояснительной записки (РПЗ).

**Задание:**
1.  **Аутентификация**: Реализация методов регистрации и входа. Хранение сессий в **Redis**, передача идентификатора через **Cookies** или **JWT**.
2.  **Автоматизация**: Автозаполнение поля "пользователь" при создании новой заявки на основе данных из сессии.
3.  **Swagger**: Полное описание всех методов API, включая модели запросов и ответов.
4.  **Разграничение прав (Permissions)**:
    *   **Гость**: Только чтение (GET) данных.
    *   **Авторизованный пользователь (Создатель)**: Доступ к своим заявкам, создание новых.
    *   **Модератор**: Полный доступ ко всем заявкам, возможность их завершения и редактирования.
5.  **Документация**: Оформление РПЗ (титульный лист, расчет аппаратных требований, расчет объема БД на 5 лет, ТЗ, таблица методов).

**Порядок показа:**
1.  **Swagger и Аутентификация**: В режиме инкогнито выполнить вход через Swagger. Получить список заявок.
2.  **Перехват сессии**: Из вкладки *Application* браузера (или из ответа API) скопировать Cookie/JWT и использовать их для авторизации запросов в **Insomnia/Postman**.
3.  **Тестирование прав (Insomnia)**:
    *   `GET` списка заявок: гость — 401/403, создатель — только свои, модератор — все.
    *   `PUT` завершения заявки: создатель — 403, модератор — успех (200) и обновление данных.
4.  **Инспекция Redis**: Демонстрация содержимого Redis через терминал (`redis-cli`), отображение данных текущего пользователя в сессии.
5.  **Архитектура**: Показ в StarUML диаграммы последовательности (Sequence), где сообщения связаны с методами классов (свойство `signature`).
6.  **Отчетность 2025**: Демонстрация изменений в **ТЗ по 2025 году** и расчетной части РПЗ.

**Диаграммы (Sequence Diagram):**
*   **Полный цикл бизнес-процесса**: Аутентификация -> Список услуг -> Работа с корзиной (добавление/просмотр/редактирование) -> Формирование заявки -> Список заявок -> Модерация -> Итоговый расчет.
*   **Требования**: Использование доменов в качестве Lifeline, передача аргументов в скобках у Message, соответствие методов диаграмме классов.

**Состав РПЗ (Документация):**
*   **Расчет аппаратных требований**: Формулы расчета CPU и RAM (4 ГБ на 1 ядро) исходя из RPS и количества пользователей.
*   **Объем БД**: Побайтовый расчет полей таблиц с учетом прироста за 5 лет.
*   **Приложение 1 (ТЗ)**: Цели, задачи (12 пунктов), функциональные требования (14 подпунктов: роли гость/создатель/модератор).
*   **Приложение 2**: Таблица всех методов веб-сервиса.

**Контрольные вопросы:**
*   **Аутентификация и авторизация**: Различия, способы реализации.
*   **Сессии и Куки**: Механизм работы, безопасность.
*   **Redis**: Почему используется для сессий, основные команды.
*   **JWT**: Структура токена, преимущества и недостатки.
*   **SSO и 2FA**: Понятия и принципы работы.
*   **RSA**: Принципы асимметричного шифрования.
